# Tetra Trigger Display

Drive a Mobile Pixels Tetra over USB-A without the vendor driver. No kernel extension, no DriverKit extension, nothing installed.

```cpp
#include <tetra/display.hpp>

tetra::Display display;
display.setMode(*display.nativeMode());
display.setPowered(true);

tetra::Surface frame(pixels, 1280, 800, pitch, tetra::PixelFormat::rgb);
display.present(frame);
```

## Device

```
0711:560b  MCT Corp.  Mobile Pixels Display Device
  interface 0  class 0xff
    ep 0x81 IN  bulk      1024 bytes
    ep 0x02 OUT bulk      1024 bytes
    ep 0x83 IN  interrupt 64 bytes
```

`0x0711` is Magic Control Technology, `0x560b` their Trigger 6. Frames are JPEG: the adapter's decoder writes NV12 into VRAM, so a full-screen update at 1280x800 costs around 20 KB.

## Build

```
brew install cmake pkg-config libusb jpeg-turbo sdl2
cmake -S . -B build
cmake --build build -j
```

libusb and libjpeg-turbo are required; libjpeg-turbo must be 3.0 or newer for the `tj3` API. SDL2 is optional and only enables the `sdl_mirror` example.

## Examples

Common flags: `--device N`, `--mode WxH`, `--quality N`, `--seconds N`, and `--free` to disable refresh-rate pacing. Native timing is used by default.

```
./build/testcard                      # BBC Test Card F, 4:3 pillarboxed
./build/testcard --fill --save a.jpg  # full bleed, also written to a file
./build/gallery --delay 3 ~/Pictures  # cycle JPEGs, letterboxed
./build/bounce                        # bouncing logo, partial updates
./build/bounce --full                 # ...whole frames instead
./build/sdl_mirror                    # render with SDL, present to the panel
```

`examples/logo.hpp` and `examples/font.hpp` are generated by `tools/`, not by the build.

## Use in your project

Configuring exports a package into the build tree; no install step needed.

```cmake
find_package(tetra REQUIRED PATHS /path/to/tetra-trigger-display/build)
target_link_libraries(yours PRIVATE tetra::tetra)
```

`add_subdirectory` also works and skips the examples when not top level. Install rules and a versioned config are generated if wanted.

`tetra::Surface` is a non-owning view of pixel data: base pointer, dimensions, pitch, format. `PixelFormat` names byte order in memory, not packed word order, so SDL's `SDL_PIXELFORMAT_ARGB8888` is `bgrx` here. `present` encodes and sends synchronously; `presentJpeg` skips the encoder if you already have a JPEG at the panel's resolution. See `examples/sdl_mirror.cpp`.

Partial updates are opt-in:

```cpp
display.setPartialUpdates(true);
display.present(surface);                  // diffs against the last frame
display.present(surface, dirty);           // or name the region
display.present(surface, regions, count);  // or several
```

## Protocol notes

Bring-up:

1. `SetConfiguration(1)`, claim interface 0
2. `0xC0 0xB0` wIndex 0..4 — hardware, boot, image, project, command versions
3. `0x40 0x31` wValue 0, wIndex 0 — software ready
4. `0xC0 0x84`, `0xC0 0x89` — mode count, then the timing table
5. `0x40 0x12` — 32-byte timing record
6. `0x40 0x31` again, then `0x40 0x03` wIndex 1 to enable the output
7. Frames over bulk `0x02`

Things that are not obvious:

- **The timing record is not echoed back verbatim.** `FNUM`, `FDEN`, `IDIV` and `OutputSelect` must be recomputed from the pixel clock against a 40 MHz base, or 48 MHz when the hardware platform version is 0.
- **1280x800 is not in the adapter's mode table**, which holds only four CEA modes. The panel's native mode is synthesised from the EDID detailed timing and sent with bit 0 of `Flag` set to mark it custom.
- **Partial updates use `VIDEO_CMD_FB_DIRECT`, not `VIDEO_CMD_CLIP_PRIMARY`.** Clip looks like the obvious command and is a trap: its `StartX`/`StartY` are ignored, and it lands at the wrong horizontal offset depending on position with no error reported. The vendor driver never issues it.
- **There is no vblank signal**, at any layer, and the interrupt endpoint coalesces so fences cannot pace a render loop. Match the mode's refresh rate instead; that is what the vendor does.

A frame is two bulk writes: a 32-byte `BulkCommand`, then a 48-byte `FlipHeader` or `DirectHeader` followed by the JPEG, padded to `jpegSize + 48 + 1024`. Placement is by destination address: `frame + y * pitch + x` for luma, `frame + lumaBlock + (y / 2) * pitch + x` for chroma. Whole frames alternate between two buffers; partial updates upload into the back buffer and then flip. See `include/tetra/protocol.hpp`.

Set `TETRA_TRACE_CLIPS` in the environment to print every region submitted.

## Touch

Touch does not come over USB-A. The vendor driver declares only video and audio user clients, and nothing in its package mentions HID, touch or digitizers. Over DisplayPort alt mode the panel presents touch as a separate USB device, `2575:fe13` behind a Genesys hub; on this connection it is not on the bus. DDC goes too, since brightness and colour ride on `IOAVServiceReadI2C` against a real DisplayPort service.

## Layout

```
include/tetra/   public headers
src/             library
examples/        testcard, gallery, bounce, sdl_mirror
tools/           generators for the logo trace and the font
python/          original probe and bring-up scripts
```

`python/probe.py` is read-only and the quickest check that an adapter responds:

```
uv run --with pyusb --with libusb1 python/probe.py
```
